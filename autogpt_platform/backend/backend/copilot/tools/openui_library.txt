Create an interactive view inside the current AutoGPT Copilot conversation. The source argument must contain only OpenUI Lang using this component library, without Markdown fences or JavaScript.

## Syntax Rules

1. Each statement is on its own line: `identifier = Expression`
2. `root` is the entry point — every program must define `root = Workspace(...)`
3. Expressions are: strings ("..."), numbers, booleans (true/false), null, arrays ([...]), objects ({...}), or component calls TypeName(arg1, arg2, ...)
4. Use references for readability: define `name = ...` on one line, then use `name` later
5. EVERY variable (except root) MUST be referenced by at least one other variable. Unreferenced variables are silently dropped and will NOT render. Always include defined variables in their parent's children/items array.
6. Arguments are POSITIONAL (order matters, not names). Write `SomeComp([children], "row", "l")` NOT `SomeComp([children], direction: "row", gap: "l")` — colon syntax is NOT supported and silently breaks
7. Optional arguments can be omitted from the end
- Strings use double quotes with backslash escaping

## Component Signatures

Arguments marked with ? are optional. Sub-components can be inline or referenced; prefer references for better streaming.

Workspace(title: string, description: string, children: (Metrics | Chart | DataTable | Insight | Checklist | Form | FollowUp | Map | Timeline | TrendChart | DonutChart)[]) — The root workspace. Give it a concise title, summary, and up to eight useful sections.
Metric(label: string, value: string, detail: string, tone: "neutral" | "positive" | "warning") — A single KPI with a label, formatted value, supporting detail, and tone.
Metrics(items: Metric[]) — A responsive row of two to four metrics.
Chart(title: string, description: string, unit: string, points: {label: string, value: number}[]) — An interactive bar chart with at most 24 points. Values must be nonnegative numbers. Unit explains the y-axis.
DataTable(title: string, columns: string[], rows: string[][]) — A searchable, sortable table with at most six columns and 30 rows. Each row must have one string per column. Split larger datasets across tables without dropping rows.
Insight(title: string, body: string, tone: "neutral" | "positive" | "warning") — A short takeaway, recommendation, or caveat. Use warning for missing data.
Checklist(title: string, items: {title: string, detail: string}[]) — An interactive checklist with at most 12 items that the user can tick off locally. Split longer lists into multiple checklists without dropping tasks. This does not execute tasks.
Field(name: string, label: string, value: string, placeholder: string) — An editable, labeled text field inside a Form. Use a unique name.
Form(name: string, title: string, fields: (Field | SelectField | DateField | NumberField)[], submitLabel: string, message: string) — Collect a brief with at most six fields. Submitting sends the edited values to the assistant; no external action is executed.
FollowUp(label: string, message: string) — A follow-up button that asks the assistant to update the workspace. Never imply an external task was performed.
Map(title: string, description: string, locations: {name: string, latitude: number, longitude: number, detail: string, category: string}[]) — An interactive geographic map with one to 50 numbered markers, searchable places, details, zoom, and a button to discuss the selected place in this chat. Supply verified latitude/longitude from the user or tools; never guess coordinates. This does not geocode, calculate routes, or request the user's location.
Timeline(title: string, items: {time: string, title: string, detail: string, status: "done" | "current" | "planned"}[]) — A chronological itinerary, milestone plan, or event history with at most 20 items. Preserve supplied dates and time zones; label proposed times as a plan.
TrendChart(title: string, description: string, unit: string, points: {label: string, value: number}[]) — An interactive line chart for at most 60 ordered observations or time series points. Values may be negative. Include only supplied observations; never invent missing periods.
DonutChart(title: string, description: string, unit: string, points: {label: string, value: number}[]) — A part-to-whole breakdown with at most 12 categories, a total, legend, values, and percentages. Use nonnegative amounts in the same unit; do not combine overlapping categories.
SelectField(name: string, label: string, value: string, options: {label: string, value: string}[]) — A labeled dropdown with one to 12 options inside a Form. The initial value must match an option value. Use unique nonempty option values.
DateField(name: string, label: string, value: string | "") — A calendar date input inside a Form. Use YYYY-MM-DD, or an empty string when the user should choose. This does not schedule anything.
NumberField(name: string, label: string, value: number, min?: number, max?: number, step: number) — A numeric input inside a Form. Provide a numeric initial value, minimum/maximum (null if unbounded), and a positive step. The initial value must satisfy those constraints.

## Hoisting & Streaming (CRITICAL)

openui-lang supports hoisting: a reference can be used BEFORE it is defined. The parser resolves all references after the full input is parsed.

During streaming, the output is re-parsed on every chunk. Undefined references are temporarily unresolved and appear once their definitions stream in. This creates a progressive top-down reveal — structure first, then data fills in.

**Recommended statement order for optimal streaming:**
1. `root = Workspace(...)` — UI shell appears immediately
2. Component definitions — fill in as they stream
3. Data values — leaf content last

Always write the root = Workspace(...) statement first so the UI shell appears immediately, even before child data has streamed in.

## Examples

root = Workspace("Weekly overview", "Illustrative sample data", [stats, note])
stats = Metrics([Metric("Completed", "42", "This week", "positive")])
note = Insight("Next step", "Compare this with last week before drawing conclusions.", "neutral")

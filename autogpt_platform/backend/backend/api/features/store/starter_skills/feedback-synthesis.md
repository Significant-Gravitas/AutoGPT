# Feedback synthesis

Use this for a batch of tickets, notes, survey answers, or reviews.

## Clean and tag

State the sources, the period, and the number of items from each. Remove
exact duplicates and note how many. Tag each item with the account, segment,
plan, and source. Mark items too vague to use rather than forcing them into a
theme.

## Group into problems

Group by the problem the user has, not the solution they asked for. For each
problem note who has it, how often, what they do today, and what it costs
them. One loud request is not a pattern, and silence is not satisfaction.
Keep what users said apart from what you infer.

## Evidence table

For each problem return:

| Problem | Items | Accounts | Segments | Sources | Example quote |
|---|---|---|---|---|---|

Quote users word for word, with the source and date. Mark each theme
**strong**, **moderate**, or **thin**, and say why. List what the data cannot
show, such as users who never write in.

Never invent a quote, a count, or a segment, and never drop feedback that
disagrees to make a theme look stronger. Do not edit the tracker yourself.
